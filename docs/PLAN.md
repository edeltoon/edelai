# **이 기획서의 결론**

우리 서비스는 AI 사용을 감시하거나 금지하는 도구가 아니다. 대학 공식
계정과 과목 공간을 기반으로 학생이 AI의 답변을 검증하고, 오류를
찾아내고, 근거를 설명한 과정을 평가하는 대학 학습 인프라다.

학생에게는 AI를 잘 활용하면서 추가 점수와 역량 기록을 얻는 학습 공간을
제공하고, 교수에게는 학생들이 어떤 개념에서 막히는지와 AI를 어떻게
사용했는지를 자동 요약해 제공한다.

# **서비스 한 문장**

**AI에게 정답을 묻는 대학에서, AI의 오답을 검증하는 대학으로 바꾼다.**

| **구분**  | **내용**                                                                                       |
|-----------|------------------------------------------------------------------------------------------------|
| 문제      | 생성형 AI가 과제와 답변을 대신 만들면서 결과물만으로 학생의 실제 이해도를 확인하기 어려워졌다. |
| 핵심 발상 | AI가 과목별로 승인된 그럴듯한 오류를 제시하고, 학생이 오류를 찾아 근거와 함께 수정하게 한다.   |
| 학생 가치 | AI 사용을 금지하지 않으면서 검증 능력, 설명력, 비판적 사고에 추가 점수와 역량 기록을 제공한다. |
| 교수 가치 | 모든 프롬프트를 읽지 않아도 AI가 학습 흐름과 오개념을 요약해 수업 개선에 활용할 수 있다.       |

# **1 문제 정의**

현재 대학의 과제 평가는 완성된 결과물을 중심으로 이루어진다. 하지만
생성형 AI는 보고서, 코드, 발표문, 풀이를 짧은 시간 안에 만들어준다.
결과물이 완벽해 보여도 학생이 개념을 이해했는지, AI의 오류를 확인했는지,
근거를 판단했는지 알기 어렵다.

AI 사용을 단순히 금지하는 방법은 현실성이 낮다. 중요한 능력은 AI를
사용하지 않는 능력이 아니라, AI가 만든 결과를 검증하고 책임 있게
수정하는 능력이다.

## **우리가 바꾸려는 평가 질문**

| **기존 평가 질문**         | **새로운 평가 질문**                               |
|----------------------------|----------------------------------------------------|
| 이 과제는 AI가 작성했는가? | AI를 사용했어도 학생이 내용을 이해하고 판단했는가? |
| 최종 답이 맞는가?          | 왜 맞는지, 어떤 근거로 판단했는가?                 |
| 결과물이 완성됐는가?       | 오류를 발견하고 결과를 개선할 수 있는가?           |
| 학생이 답을 외웠는가?      | 새로운 사례에 개념을 적용하고 설명할 수 있는가?    |

# **2 서비스 개념**

학생은 학교 계정으로 로그인하고 수강 중인 과목 공간에 들어간다. 과목별
AI는 교수님이 제공한 강의자료, 교재 범위, 핵심 개념을 바탕으로 학생의
질문과 과제를 돕는다. 단, 학습 활동 중 일부에는 교수님이 승인한 ‘검증
챌린지’가 포함된다.

**학교 계정 로그인 → 과목 선택 → AI 학습·과제 → 오류 검증 → 추가
점수·역량 기록**

## **서비스의 세 가지 모드**

| **모드**         | **학생 경험**                                      | **평가 목적**                  |
|------------------|----------------------------------------------------|--------------------------------|
| 일반 학습 모드   | 강의자료를 근거로 AI에게 질문하고 개념을 연습한다. | 개념 이해와 학습 보조          |
| 검증 챌린지 모드 | AI가 제시한 답변에서 오류를 찾고 근거를 제출한다.  | AI 리터러시와 비판적 사고 평가 |
| 과제 방어 모드   | 학생이 제출한 과제에 대해 개인별 질문에 답한다.    | 실제 이해도와 설명 능력 확인   |

# **3 학생 사용 흐름**

## **3 1 학교 계정과 과목 공간**

학생은 학교 이메일 또는 대학 포털 계정으로 로그인한다. 수강신청 정보와
연결하면 본인이 수강하는 과목만 자동으로 표시된다. 별도의 공개 챗봇이
아니라 ‘서양철학’, ‘미적분’, ‘자료구조’처럼 과목마다 지식 범위와 평가
규칙이 다른 공간을 제공한다.

## **3 2 검증 챌린지**

AI가 무작위로 아무 말이나 틀리게 하는 방식은 사용하지 않는다. 교수님이
승인한 강의자료와 오개념 목록을 기반으로, 학습에 도움이 되는 오류를
제한적으로 제시한다.

| **오류 유형** | **서양철학 예시**                       | **학생이 해야 할 일**          |
|---------------|-----------------------------------------|--------------------------------|
| 개념 반전     | 감각 세계가 진정한 실재라는 설명        | 이데아론의 실재관을 반박       |
| 개념 혼동     | 플라톤과 아리스토텔레스의 관점 혼합     | 두 철학자의 차이를 근거로 설명 |
| 근거 누락     | 동굴의 비유를 설명하면서 핵심 단계 누락 | 강의자료의 핵심 요소 추가      |
| 허위 출처     | 존재하지 않는 책이나 문장 인용          | 출처 확인 후 신뢰도 판단       |

## **3 3 학생 답변과 점수**

학생은 오류가 있다고 생각하는 문장을 선택하는 데서 멈추지 않고, 왜
그렇게 판단했는지 본인의 생각을 먼저 작성한다. 그 다음 올바른 내용과
근거를 연결한다. 단순히 ‘틀렸다’고 표시하거나 AI의 정답 문장을 복사하는
것만으로는 높은 점수를 받을 수 없다.

모든 주장을 틀렸다고 표시하는 전략을 막기 위해 실제 판정 정확도와
확신도를 함께 반영한다. 오류를 찾는 것뿐 아니라 맞는 주장을 맞다고
인정하는 능력도 평가 대상이다.

| **행동**            | **점수** | **판정 기준**                                  |
|---------------------|----------|------------------------------------------------|
| 주장별 판정         | +1       | 각 주장을 맞다 또는 틀리다로 정확히 판정했는가 |
| 본인 생각·판단 이유 | +2       | 왜 그렇게 판단했는지 자신의 말로 설명했는가    |
| 올바른 개념 제시    | +2       | 대체 설명이 강의자료와 일치하는가              |
| 근거 연결           | +2       | 강의자료·교재·공식 출처를 연결했는가           |
| 새 사례 적용        | +3       | 다른 사례에 개념을 적용할 수 있는가            |

본인 생각 점수는 모범답안과 문장이 똑같은지를 보는 점수가 아니다. 주장과
이유가 논리적으로 연결되는지, 수업 개념을 비교하거나 반례를 들어
설명하는지, 자신의 언어로 판단을 드러냈는지를 본다. 표현이 서툴러도
사고의 흔적이 있으면 점수를 받을 수 있다.

## **3 4 오류 개수와 확신도 기반 검증**

AI 답변에는 오류가 총 몇 개 있는지만 보여주고, 어떤 문장이 틀렸는지는
숨긴다. 학생은 답변을 여러 개의 주장 단위로 나누어 각 주장에 대해 ‘맞다’
또는 ‘틀리다’, 확신도 0~100, 본인의 판단 이유를 입력한다.

**오류 개수 공개 → 주장별 판정 → 확신도 0~100 → 본인 생각 작성 →
해설·재인출**

| **학생 화면** | **예시**                         | **측정되는 능력**                       |
|---------------|----------------------------------|-----------------------------------------|
| 오류 개수     | 이 답변에는 오류가 2개 있습니다. | 검증 대상의 범위를 인식                 |
| 주장 판정     | 주장 A 맞다 / 주장 B 틀리다      | 내용 정확도                             |
| 확신도        | 틀리다 · 확신도 85               | 판단 확신과 실제 정답의 일치            |
| 본인 생각     | 왜 틀렸다고 생각했는지 1~3문장   | 이유를 구성하고 개념을 자기 언어로 설명 |
| 즉시 해설     | 정답과 오류 원리 공개            | 오류를 올바른 개념으로 교정             |
| 1주 후 퀴즈   | AI 없이 같은 개념 재인출         | 장기 기억과 전이                        |

오류 개수만 알려주면 학생은 모든 문장을 틀렸다고 표시하고 싶어질 수
있다. 이 과잉교정의 유혹을 일부러 만들고, 단순한 의심이 아니라 정확한
판단과 확신도 조절 능력을 평가한다.

정답과 오류 원리 해설은 학생이 주장별 판정·확신도·본인 생각을 모두
제출한 뒤에만 열린다. 이유 칸이 비어 있으면 제출 버튼 대신 ‘왜 그렇게
생각했는지 먼저 적어보세요’라는 유도 문구를 보여준다. 제출 직후 해설을
공개하는 것은 필수 해소 단계이며, 실제 발표에서는 1주를 기다릴 수
없으므로 ‘1주 후 재인출 퀴즈 예약’ 상태와 미리 준비한 결과 화면을 이어서
보여준다.

## **3 5 정답 직행 프롬프트와 과정 감점**

Gemini 같은 외부 AI에 ‘정답 번호를 가장 먼저 알려줘’, ‘해설 없이 답만
줘’처럼 시험 답을 바로 뽑아내도록 지시하는 행동 자체를 공부로 간주하지
않는다. 다만 이런 문구를 입력했다는 이유만으로 즉시 부정행위로 확정하지
않고, 독립적인 시도 없이 답을 복사했는지와 이후 검증 과정을 함께
확인한다. 우리 서비스에서는 정답·해설을 보여주기 전에 본인의 판단 이유를
먼저 제출하게 해 정답만 가져가는 흐름을 끊는다.

| **행동**                                  | **시스템 판정**     | **점수·처리**                                   |
|-------------------------------------------|---------------------|-------------------------------------------------|
| 정답만·번호만·해설 생략 요구              | 정답 직행 요청 태그 | 경고 표시. 단독으로는 감점하지 않음             |
| 답을 그대로 복붙하고 근거·확신도 없음     | 학습 과정 우회      | 과정 점수 -2, 교수 검토 플래그                  |
| 직행 요청 후 자신의 판정·근거·확신도 제출 | 참고 후 검증        | 감점 없이 검증 점수 반영. 정답 복사 보너스 없음 |
| 활성 시험에서 반복 요청 또는 탐지 회피    | 고위험 시도         | 정답 대신 힌트·검증 모드로 전환하고 교수 검토   |

핵심은 외부 Gemini의 사용 자체를 감시한다고 과장하지 않는 것이다. 서비스
안의 프롬프트와 학생이 제출한 답변·대화 로그에서 정답 직행 패턴을
탐지하고, 최종 평가는 주장별 판정·근거·확신도·1주 후 재인출로 교차
확인한다.

# **4 의도적으로 틀린 정보를 만드는 방법**

이 서비스의 핵심은 AI의 오답이지만, 학생에게 검증되지 않은 정보를 일반
답변처럼 제공하면 안 된다. 따라서 오류는 ‘검증 챌린지’ 안에서만
작동하고, 교수님이 승인한 지식 범위와 정답 근거를 함께 보유해야 한다.

**강의자료 업로드 → 핵심 개념 추출 → 오답 후보 생성 → 교수 승인 → 챌린지
출제**

## **교수 승인 기반 오류 생성**

| **단계**  | **시스템 역할**                         | **교수님 역할**           |
|-----------|-----------------------------------------|---------------------------|
| 자료 등록 | 강의자료에서 개념·정의·예시·출처를 추출 | 강의자료와 평가 범위 등록 |
| 오답 후보 | 학생이 자주 할 법한 오류를 여러 개 생성 | 후보를 검토하고 수정      |
| 정답 근거 | 오류가 왜 틀렸는지 근거 문장 연결       | 정답 근거와 난이도 확인   |
| 출제      | 학생별·회차별로 챌린지를 배정           | 점수와 반영 비율 설정     |

## **오답 챌린지의 안전 규칙**

- 일반 답변과 검증 챌린지 답변을 화면에서 명확히 구분한다.

- 교수님이 승인하지 않은 오류는 성적에 반영하지 않는다.

- 학생이 오류를 놓쳐도 학습용 해설과 근거를 제공한다.

- 활성 시험이나 성적 반영 챌린지에서는 정답 직행 요청을 감지해 답을 바로
  > 출력하지 않고, 학생의 독립 시도와 검증 입력을 먼저 요구한다.

- 의학·법률·안전처럼 오답이 실제 피해를 만들 수 있는 분야는 데모
  > 범위에서 제외하거나 별도 제한한다.

- AI가 만든 점수는 교수님이 확인하고 조정할 수 있는 보조 지표로
  > 표시한다.

# **5 교수님 대시보드**

교수님이 모든 프롬프트를 직접 읽는 것은 불가능하다. 기본 화면에서는 AI가
전체 대화를 구조화해 요약하고, 특정 학생·개념·과제에 문제가 발견될 때만
원문을 열람할 수 있게 한다.

| **대시보드 영역** | **보여줄 내용**                                         | **교수님이 얻는 판단**                            |
|-------------------|---------------------------------------------------------|---------------------------------------------------|
| 학습 현황         | 전체 참여율, 챌린지 성공률, 평균 소요 시간              | 학생들이 활동에 참여하고 있는가                   |
| 오개념 지도       | 가장 많이 틀린 개념과 혼동 관계                         | 다음 수업에서 다시 설명할 부분은 무엇인가         |
| 학생별 기록       | 오류 발견, 본인 생각, 근거 사용, 설명력, 재시도 기록    | 학생의 실제 이해도는 어느 정도인가                |
| 이유 서술 분석    | 본인 생각 작성률, 이유의 논리 연결, 해설 전후 설명 변화 | 학생이 답을 아는지 넘어 왜 그렇게 생각하는지 판단 |
| AI 요약           | 프롬프트·답변·수정 과정을 주제별로 요약                 | 전체 대화를 읽지 않고 수업 흐름을 파악            |
| 학습 과정 보호    | 정답 직행 요청, 경고·감점, 독립 시도율                  | 답만 복사한 것인지 실제 검증했는지 판단           |
| 원문 열람         | 필요한 학생 또는 대화의 전체 기록                       | AI 요약을 확인하거나 평가 근거를 검토             |

# **6 교수님에게 제공할 AI 요약**

교수님 화면에는 단순 통계가 아니라, 다음 수업에서 행동으로 이어질 수
있는 요약이 나와야 한다. 정답률뿐 아니라 학생이 얼마나 정확하게
판단했는지, 그 판단을 얼마나 믿었는지, 일주일 뒤에도 기억하는지를 함께
보여준다.

**예시 요약** 서양철학 3주차에서 플라톤의 이데아론과 아리스토텔레스의
형상 개념을 혼동한 학생이 42명 중 27명이었습니다. 특히 ‘감각 세계가
진정한 실재’라는 AI의 설명을 그대로 수용한 비율이 26%였습니다. 다음
수업에서는 동굴의 비유와 두 철학자의 실재관을 비교하는 5분 활동을
권장합니다.

| **지표**           | **정의**                                             | **활용**                                  |
|--------------------|------------------------------------------------------|-------------------------------------------|
| 오류 발견률        | AI가 제시한 오류 중 학생이 정확히 찾은 비율          | 비판적 검증 능력 확인                     |
| 근거 사용률        | 답변에 강의자료·교재 근거를 연결한 비율              | 근거 기반 학습 여부 확인                  |
| 수정 개선폭        | 첫 답변과 재시도 답변 사이의 점수 변화               | 학습이 실제로 개선됐는지 확인             |
| AI 수용 편향       | 검증 없이 AI 답변을 수용한 비율                      | AI 리터러시 보완 필요성 파악              |
| 개념별 혼동률      | 특정 개념을 다른 개념과 혼동한 비율                  | 다음 수업 내용 조정                       |
| 확신도 보정 정확도 | 학생 확신도와 실제 판정의 차이를 계산한 지표         | 과잉확신·과소확신과 메타인지 확인         |
| 재인출 점수        | 1주 후 AI 없이 같은 개념을 다시 풀었을 때의 점수     | 단기 정답이 장기 학습으로 이어졌는지 확인 |
| 정답 직행 시도율   | 정답만 요구하거나 답변 복사를 시도한 비율            | 학습 과정 우회가 많은 지점 파악           |
| 과정 준수율        | 독립 시도·근거·확신도·해설 확인까지 완료한 비율      | 결과물이 아닌 학습 과정 평가              |
| 이유 서술 완성률   | 정답을 보기 전에 본인의 판단 이유를 작성한 주장 비율 | 오류 발견을 사고 과정으로 연결            |
| 설명 변화폭        | 해설 전 본인 생각과 해설 후 수정 설명의 차이         | 피드백이 개념 이해를 바꿨는지 확인        |

# **7 데모 버전 구현 범위**

예선 또는 아이디어톤 데모에서는 실제 대학 LMS 전체를 만드는 것보다,
하나의 과목에서 학생 화면과 교수 화면이 연결되는 모습을 완성하는 것이
중요하다.

## **데모 과목**

서양철학을 1차 데모 과목으로 사용한다. 이미 팀에서 AI 답변의 철학적 오류
문제를 직접 경험한 사례가 있어 문제 제기가 쉽고, 개념 오류를 안전하게
설계할 수 있다.

| **화면**         | **필수 기능**                                        | **데모에서 보여줄 장면**                   |

| 로그인·과목 선택 | 학생·교수 역할 선택, 과목 목록 표시                  | 학교 계정 기반 과목 공간 진입              |
| 학생 학습 화면   | 질문 입력, AI 답변, 검증 챌린지, 본인 생각 입력      | AI의 플라톤 설명에서 오류와 판단 이유 작성 |

| 교수 대시보드    | 통계, 오개념, 프롬프트 요약                          | 반 전체의 혼동 개념과 AI 요약 확인         |

- 핵심 개념 5개: 이데아론, 동굴의 비유, 소크라테스의 문답법,

- 교수 대시보드용 집계 데이터

- 1주 후 재인출 퀴즈 예약 상태와 미리 준비한 결과 데이터

## **오답 생성 프롬프트의 기본 원칙**

사용한다. 모든 오답에는 정답 주장, 근거 문장, 오류 유형, 난이도, 교수
승인 상태를 함께 저장한다.

AI에게 요구할 핵심 출력 형식은 다음과 같다.

| **필드**      | **예시**                                                  |
|---------------|-----------------------------------------------------------|
| concept       | 플라톤의 이데아론                                         |

| correct_claim | 이데아가 진정한 실재이며 감각 세계는 불완전한 모방이다.   |

| error_type    | 개념 반전                                                 |
| difficulty    | 중                                                        |

# **9 3분 데모 시나리오**

데모는 기능을 많이 보여주는 것보다, 한 명의 학생이 AI의 오류를 발견하고
교수님이 반 전체의 오개념을 확인하는 흐름을 끝까지 보여주는 것이 좋다.

| **시간**  | **화면**          | **발표 내용**                                                                               |
|-----------|-------------------|---------------------------------------------------------------------------------------------|
| 0:00–0:25 | 문제 제기         | AI가 과제를 잘 만들어주는 시대에 결과물만으로 이해도를 평가하기 어렵다는 상황 제시          |
| 0:25–0:50 | 로그인·과목 선택  | 학교 계정으로 서양철학 과목에 들어가는 흐름 시연                                            |
| 0:50–1:25 | AI 답변·직행 요청 | 정답 번호만 요구하는 프롬프트를 감지하고 검증 절차로 유도한 뒤, 그럴듯하지만 틀린 설명 제시 |
| 1:25–2:00 | 오류 검증         | 학생이 주장별 판정·확신도와 본인의 판단 이유를 먼저 쓰고 근거와 함께 제출                   |
| 2:00–2:35 | 학생 결과         | 본인 생각 제출 후 정답·오류 원리 해설을 확인하고 1주 후 AI 없는 재인출 퀴즈 예약            |
| 2:35–3:00 | 교수 대시보드     | 탐지율·확신도 보정 정확도·재인출 점수와 AI 요약을 함께 확인                                 |

# **10 데모 화면을 실제로 구성하는 방법**

데모에서는 여러 과목을 동시에 보여주지 않는다. 서양철학 한 과목, 핵심
개념 다섯 개, 오류 카드 열 개만으로 학생 화면과 교수 화면이 연결되는
모습을 완성한다.

| **순서**    | **학생 화면에서 보이는 것**                                  | **시스템 내부에서 처리하는 것**                                   |
|-------------|--------------------------------------------------------------|-------------------------------------------------------------------|
| 1 과목 진입 | 학교 계정으로 로그인하고 서양철학 과목을 선택                | 사용자 역할과 수강 과목을 확인                                    |
| 2 질문      | ‘플라톤의 이데아론을 설명해줘’ 입력                          | 과목 지식베이스를 참고해 답변 생성                                |
| 3 챌린지    | 오류 개수만 보고 주장별 판정·확신도와 본인 생각 입력         | 교수 승인 오류 카드와 정답 주장 목록을 배정                       |
| 4 제출      | 판정·확신도·본인 생각·근거 제출                              | 이유 서술 점수와 탐지율·확신도 보정 정확도를 계산                 |
| 5 해소·예약 | 본인 생각 제출 후 정답·오류 원리 해설 확인, 1주 후 퀴즈 예약 | 필수 피드백을 저장하고 재인출 퀴즈 생성                           |
| 6 교수 화면 | 교수님이 반 전체 요약과 학생별 기록 확인                     | 프롬프트를 요약하고 탐지율·보정 정확도·재인출 점수·과정 감점 계산 |

## **데모에서 사용할 실제 예시**

| **항목**         | **내용**                                                                                                                               |
|------------------|----------------------------------------------------------------------------------------------------------------------------------------|
| 학생 질문        | 플라톤의 이데아론과 우리가 보는 현실 세계의 관계를 설명해줘.                                                                           |
| AI의 의도적 오류 | 감각으로 경험하는 현실 세계가 진정한 실재이고, 이데아는 현실을 모방한 불완전한 개념이다.                                               |
| 학생의 반박      | 반대다. 플라톤은 이데아를 진정한 실재로 보고 감각 세계를 불완전한 모방으로 보았다. 동굴의 비유에서 동굴 밖의 세계가 이데아에 해당한다. |
| 근거             | 서양철학 3주차 강의자료 12쪽과 교수님이 지정한 교재의 이데아론 설명                                                                    |
| 결과             | 오류 발견 1점, 개념 수정 2점, 근거 연결 2점, 설명 2점으로 총 7점 획득                                                                  |

## **데모에서 반드시 보여줄 변화**

- 학생이 AI의 답변을 그대로 믿는 장면과 오류를 검증하는 장면을 비교한다.

- 학생 점수만 보여주지 말고, 어떤 개념을 틀렸고 어떻게 개선했는지
  > 보여준다.

- 오류 개수만 공개된 답변에서 학생이 모든 문장을 틀렸다고 하지 않고,
  > 주장별 판정과 확신도를 제출하는 장면을 보여준다.

- ‘정답 번호를 가장 먼저, 해설 없이 알려줘’ 같은 정답 직행 프롬프트를
  > 입력하면 경고가 뜨고, 답을 복사해 근거 없이 제출할 경우 과정 점수
  > -2가 표시되는 장면을 보여준다.

- 학생이 정답을 보기 전에 ‘나는 왜 이 주장이 맞거나 틀리다고
  > 생각하는가’를 자기 말로 1~3문장 작성하고, 해설 전후의 설명 변화를
  > 비교하는 장면을 보여준다.

- 제출 직후 정답과 오류 원리 해설을 보여주고, ‘1주 후 AI 없는 재인출
  > 퀴즈가 예약되었습니다’라는 상태를 표시한다.

- 교수님이 수십 개의 대화를 읽지 않고 한 문단의 AI 요약으로 반 전체
  > 오개념을 확인하는 장면을 보여준다.

- 교수 대시보드에서 탐지율·확신도 보정 정확도·재인출 점수를 함께
  > 비교한다.

- 마지막에 ‘이 학생은 과제를 제출했다’가 아니라 ‘AI 답변을 검증하고
  > 근거를 제시했다’는 역량 카드가 생성되도록 한다.

# **11 구현 순서**

1.  서양철학 핵심 개념 5개와 승인된 오류 카드 10개를 먼저 만든다.

2.  학생 화면에서 질문 입력과 AI 답변이 작동하도록 만든다.

3.  검증 챌린지에서 주장별 판정, 본인 생각 입력, 근거 입력, 점수 계산을
    > 구현한다.

4.  본인 생각 제출 전에는 정답 해설을 잠그고, 제출 후 초기 생각과 교정된
    > 설명을 비교해 보여준다.

5.  학생 결과 화면에 주장별 판정·확신도, 이유 서술 점수, 즉시 해설, 오류
    > 발견률을 표시한다.

6.  1주 후 AI 없는 재인출 퀴즈를 예약하고, 재인출 점수와 확신도 보정
    > 정확도를 계산한다.

7.  정답 직행 요청·답변 복사 패턴을 태깅하고, 조건을 충족할 때만 과정
    > 점수 감점을 적용한다.

8.  학생 데이터를 집계해 교수 대시보드와 AI 요약을 구현한다.

9.  같은 흐름을 다른 과목에도 적용할 수 있도록 과목·오류 카드를 데이터로
    > 분리한다.

# **12 아이디어톤 평가 기준과의 연결**

| **평가 기준** | **우리 아이디어가 보여주는 내용**                                                       |
|---------------|-----------------------------------------------------------------------------------------|
| 주제 적합성   | 생성형 AI로 결과물의 진위와 이해도를 구분하기 어려워진 대학 평가 문제를 직접 해결한다.  |
| 논리성        | AI 사용 확산 → 결과물 평가 한계 → 오류 검증형 학습 → 과정 중심 평가의 흐름이 명확하다.  |
| 근거의 체계성 | 실제 AI 오답 사례, 학생의 오개념 데이터, 챌린지 성공률과 교수 대시보드 지표를 활용한다. |
| 창의성        | AI를 탐지하거나 차단하는 대신, AI가 틀릴 수 있는 환경을 만들고 오류 발견을 점수화한다.  |
| 문제 해결력   | 학교 계정, 과목별 지식베이스, 학생 평가, 교수 요약까지 실제 사용 흐름을 설계했다.       |

# **마지막 한 문장**

**우리는 AI가 정답을 알려주는 대학을 만드는 것이 아니라, AI의 답을
의심하고 검증하고 설명할 수 있는 학생이 더 높은 평가를 받는 대학을
만든다.**

이 서비스의 첫 기능은 ‘틀린 AI 답변 찾기’지만, 최종 목표는 대학 성적표를
결과 중심 기록에서 사고 과정과 AI 협업 역량을 보여주는 학습 프로필로
진화시키는 것이다.
