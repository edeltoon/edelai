# EdelAI 개발 기준

## 목표와 현재 상태

Claude API를 실제 호출하는 대학 학습·평가 서비스를 만든다.
자체 모델 훈련이 아니라 기존 Claude 모델에 강의자료와 학습 규칙을 제공하는 방식이다.
현재 Next.js 초기 환경, 실행 확인용 페이지, `POST /api/chat` 서버 연결 코드가 구현되어 있다.
API의 실제 호출에는 로컬 키·모델 설정이 필요하며, 연결 코드 테스트와 실제 호출 검증을 구분한다.
사용법은 `docs/API.md`를 참고한다. 나머지 화면·데이터 흐름은 앞으로 구현할 계획이다.

팀원이 전달한 ZIP은 참고 자료다. 목데이터 전용, 실제 LLM 호출 금지,
GitHub Pages 정적 배포 전제는 채택하지 않는다.
이번에 합의한 실제 Claude 연동 방향과 이후 팀의 명시적인 결정이 우선한다.

## 역할 분담

| 담당 | 범위 |
| --- | --- |
| 사용자 | 교수 화면, 서버 API, Claude 연동 |
| 팀원 | 학생 화면, 서버 API를 사용하는 입력·응답·결과 표시 |
| 함께 결정 | 공통 레이아웃·컴포넌트 담당, 요청·응답 형식, 데이터 저장 방식, 배포 환경 |

학생 화면은 `src/app/student/`, `src/features/student/`를 사용한다.
교수 화면은 `src/app/professor/`, `src/features/professor/`를 사용한다.
서버 API는 `src/app/api/`, 서버 전용 Claude 처리는 `src/lib/server/`로 분리한다.
공통 타입은 `src/types/`, 공용 UI는 `src/components/`에 둔다.
교수·학생 화면 경로는 아직 생성하지 않았다. 서버 API와 공통 대화 타입 경로는 구현했다.

## 실행 구조

학생·교수 브라우저 → Next.js 서버 API → Claude → 서버 응답 → 화면 표시

- 기존 Next.js App Router·TypeScript·Tailwind·ESLint·npm을 유지한다.
- 첫 단계에서는 별도 FastAPI 서버를 추가하지 않고 Next.js Route Handlers를 사용한다.
- 키는 서버 환경 변수 `ANTHROPIC_API_KEY`로 관리한다. 브라우저에 전달하지 않는다.
- 사용할 Claude 모델은 실제 연동 시 계정에서 사용할 수 있는 모델을 확인해 선택한다.
- 외부 API 실패나 설정 누락은 오류로 표시한다. 준비된 답변을 실제 AI 응답처럼 대신 보여주지 않는다.
- 목데이터는 화면 개발과 테스트에 사용할 수 있지만 실제 호출과 명확하게 구분한다.
- 실제 학교 로그인과 DB 도입은 별도 단계에서 결정한다.
- localStorage는 브라우저별 보조 상태다. 학생·교수 간 공유 기록의 저장소로 간주하지 않는다.

## 학습 흐름

1. 학생이 과목에 대해 질문하고 실제 Claude 응답을 받는다.
2. 강의자료 기반 응답과 근거 표시를 추가한다. 근거가 없는 인용은 만들어내지 않는다.
3. 교수는 오류 카드 후보·정답·근거를 검토하고 승인한다.
4. 학생은 승인된 챌린지에서 주장별 판정·확신도·이유를 제출한다.
5. 서버가 제출을 확인한 뒤 정답·해설을 공개한다.
6. 교수는 학생 기록과 AI 분석 제안을 검토하고 최종 평가를 확정한다.
7. 재인출 퀴즈는 위 흐름이 연결된 다음 추가한다.

일반 학습 답변에 의도적인 오류를 섞지 않는다. 의도적인 오류는 안내된 검증 챌린지에서만 사용한다.
제출 전 학생 응답·HTML·클라이언트 번들에 정답을 포함하지 않는다.
학생·교수 데이터 접근 검사는 실제 인증 및 저장 설계를 정할 때 함께 구현한다.
역할 선택만으로 실제 접근 제어가 완성된 것으로 취급하지 않는다.

## 구현 순서

1. 서버에서 Claude에 질문 하나를 전달하고 실제 답변을 받는 최소 API를 만든다.
2. 요청·응답·오류 형식을 팀원과 공유하고 학생 채팅에 연결한다.
3. 과목 및 강의자료 컨텍스트를 연결한다.
4. 교수 오류 카드 검토·승인 화면과 API를 만든다.
5. 저장 방식을 결정하고 승인·학생 제출·해설·교수 조회를 끝까지 연결한다.
6. 평가 확정 및 재인출 흐름을 추가한다.

첫 API 완료 기준: 유효한 요청으로 실제 응답 수신, 잘못된 입력 거절,
키 미설정 및 외부 API 실패 처리, 브라우저 응답에 키 미포함, 린트·빌드 통과.
키가 없는 상태의 검사는 실제 Claude 호출 성공 검증과 구분해서 보고한다.

## 배포와 협업

- 정적 export를 사용하지 않는다. GitHub Pages 단독 배포를 기준으로 삼지 않는다.
- Next.js 서버 실행이 가능한 배포 환경을 선택한다. 지금은 로컬에서 진행한다.
- basePath를 추가하지 않으며 로컬 주소는 `http://localhost:3000`이다.
- 기능 브랜치 → PR → 상대 검토 → 머지 순서로 협업한다.
- 공통 파일과 API 형식 변경은 학생 담당자에게 전달한다.
- API 키·실제 학생 개인정보는 저장소에 넣지 않는다.
