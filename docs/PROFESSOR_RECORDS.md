# 교수 학생 기록 화면

`/professor/course/phil/records`에서 서양철학 제출 기록과 대화 원문을 조회한다.
교수 챌린지 관리 화면의 학생 기록 탭에서도 접근할 수 있다.

## 현재 연결

학생 기반 PR #6의 저장 키 계약을 참고한 읽기 전용 임시 어댑터:
`src/features/professor/records/reader.ts`의 `loadRecords`.
아직 머지되지 않은 학생 코드에 의존하지 않으며 학생 코드·공용 타입을 변경하지 않는다.

- `edeltoon:student-index`: 학생 ID 목록
- `edeltoon:student:{id}:submissions`: 제출 기록
- `edeltoon:student:{id}:conversations`: 대화 원문
- `edeltoon:store-change` 및 브라우저 `storage` 이벤트로 다시 읽기
- `courseId: phil`, 학생 ID, 제출 스키마 버전 1, 화면에서 사용하는 필드를 검증
- 미제출 `drafts`, 다른 과목의 기록은 표시하지 않음
- 잘못된 형식과 저장소 접근 실패는 경고로 표시하며 원본은 수정하지 않음

같은 브라우저의 같은 origin(프로토콜·호스트·포트)에서만 데이터가 공유된다.
예를 들어 localhost:3000과 localhost:3102는 서로 다른 저장소다.
실제 학생 화면과의 통합은 PR #6 및 후속 학생 UI 머지 후 동일 주소에서 확인해야 한다.

`화면 예시 보기`는 직접 작성한 가상 학생 1명의 기록을 명시적으로 선택하는 기능이다.
예시는 localStorage에 기록하지 않고 실제 기록과 섞지 않는다.

## 표시 범위와 제한

학생 ID 검색, 제출 목록, 점수 항목, 확신도 보정, 주장별 제출 원문,
해설 전후 설명, 접을 수 있는 대화 원문을 제공한다.
`grader`는 mock/server/미확인으로 구분한다. 로컬의 server 표시는 서버 진위를 보증하지 않는다.
로컬 데이터는 사용자가 수정할 수 있어 공식 평가 자료가 아니며, 이 화면에서 새 채점이나 평가 확정을 하지 않는다.
학생 이름·명부, 재인출 결과, 수업 분석, 최종 평가 저장은 다음 단계다.

공용 DB·권한 설계가 확정되면 reader를 서버 학생 기록 조회 API로 교체한다.
현재 역할 선택은 데모 UI이며 실제 인증·학생별 접근 권한을 제공하지 않는다.

## 팀원 환경 변수 요청 반영

`.env.example`에 `NEXT_PUBLIC_CHALLENGE_API=mock`을 추가했다.
현재 학생 PR의 시연용 채점 선택자이며 서버 챌린지 API 구현 후 live로 바꾼다.
mock 모드는 정답이 클라이언트 산출물에 포함되므로 학습 규칙을 보장하는 실제 서비스로 배포하지 않는다.
실제 API 키는 `.env.local`의 서버 변수 `ANTHROPIC_API_KEY`에만 넣는다.

## 검증

`npm run test:api`에 저장 키 호환·과목 필터·미제출 답안 미열람·잘못된 기록·저장소 오류 테스트가 포함된다.
실제 학생 UI와의 종단 간 통합은 별도 확인이 필요하다.
