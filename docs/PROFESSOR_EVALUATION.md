# 교수 평가 검토 초안

학생 기록 화면의 각 제출 원문 아래에 검토 입력을 제공한다.
기존 점수를 보면서 0~7점(소수 첫째 자리)의 교수 검토 점수, 수정 사유, 학생 피드백을 작성할 수 있다.
점수 변경 시 사유, 피드백, 원문 직접 확인 체크가 필요하다. 입력을 수정하면 확인 체크를 해제한다.

검토 초안 미리보기에는 기존 점수와 검토 점수, 사유, 피드백을 구분한다.
서버·localStorage·학생 원본을 변경하지 않는다. 새 AI 채점이나 실제 평가 확정은 하지 않는다.
초안은 컴포넌트 메모리에만 있으며 학생 전환·검색·화면 이동·새로고침 시 사라질 수 있다.
원본 제출 내용이 바뀌면 이전 초안이 다른 원본에 적용되지 않도록 초안을 초기화한다.
평가 확정 버튼은 서버 연결 전까지 비활성화한다.

## Supabase 통합 시 남은 일

팀원의 DB 계약 확인 후 교수 권한 검증, 제출 ID 및 버전 연결, 점수/사유/피드백 서버 검증,
확정 이력 및 중복 요청 처리, 학생별 조회 권한을 구현한다. UI만으로 접근 권한을 보장하지 않는다.
현재 draft 타입은 화면 입력용이며 확정된 DB 테이블이나 API 계약이 아니다.

이 브랜치는 수업 분석 PR #10 및 학생 기록 PR #8을 기반으로 한다.
검증: 점수 범위·정밀도·수정 사유·필수 피드백·원문 확인·입력 길이 자동 테스트.

## 채점 대기 호환
학생 계약의 reasoning/concept null 값을 제외하지 않고 '채점 대기'로 표시한다.
대기 여부는 해당 항목의 null 값을 기준으로 판단한다. 0점과 구분한다.
교수 검토에서 미채점 항목을 각각 0·1·2점으로 입력하고 기존 판정·근거·감점 및 이미 채점된 항목은 유지한다.
합계는 0~7로 제한한다. 입력값은 초안에만 반영하며 원본 pendingReview를 해제하거나 DB를 저장하지 않는다.
팀원 DB 계약에서 항목별 점수와 professor_score를 어떻게 저장하는지 확인 후 서버 저장을 연결한다.
