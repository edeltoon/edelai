# 학습 루프 규칙 (서비스의 핵심. 편의를 위해 깨지 않는다)

이 서비스는 "예측 → 충돌 → 해소 → 재인출" 순서로 이해를 만든다.
학생이 먼저 답을 걸고(판정+확신도+이유), 정답과 부딪히고, 반드시 해설로 해소하고, 1주 뒤 AI 없이 다시 꺼낸다.
의도적 오답은 공개·해소 단계 없이 노출되면 오개념을 심을 수 있으므로 아래 규칙은 예외 없이 지킨다.

## 화면 흐름 규칙
1. **구분**: 오류가 섞인 답변은 검증 챌린지 화면에서만, ChallengeBanner와 함께 보여준다. 일반 학습 모드 답변에는 의도적 오류를 넣지 않는다.
2. **개수만 공개**: "오류 N개"만 보여주고 어떤 주장이 틀렸는지는 제출 전까지 화면(스타일, 순서, 툴팁, DOM 속성, 콘솔 로그)으로 드러내지 않는다. 주장 순서는 오류 여부와 무관하게 고정. (정적 데모라 번들 안에는 답이 있지만, 화면·props로 새지 않게 하는 것이 기준)
   Next.js 주의: 서버 컴포넌트(`page.tsx`)에서 클라이언트 컴포넌트로 넘긴 props는 HTML의 RSC 페이로드에 그대로 박힌다. 챌린지 화면에는 주장의 `id`·`text`만 넘기고 `errorCardId`·정답 정보는 넘기지 않는다. 채점·해설은 제출 후 결과 화면에서 `src/lib`로 처리한다.
3. **이유 먼저**: 모든 주장에 판정과 확신도가 있고, 각 주장의 이유 칸이 비어 있지 않아야 제출 버튼이 활성화된다. 비어 있으면 버튼 자리에 "왜 그렇게 생각했는지 먼저 적어보세요".
4. **해설 필수**: 제출 직후 모든 주장의 RevealCard(정답 주장 + 근거 + 오류 유형)를 보여준다. 해설을 건너뛰는 버튼을 만들지 않는다.
5. **교수 승인**: `approvalStatus === 'approved'`인 오류 카드만 챌린지에 출제되고 점수에 반영된다.
6. **AI 점수는 보조**: 모든 점수 화면에 "AI 채점은 보조 지표이며 교수님이 조정할 수 있어요" 문구.

## 점수 계산 (`src/lib/scoring.ts`, 순수 함수)
주장 하나당:
| 항목 | 점수 | 데모 판정 방식 |
|---|---|---|
| 판정 정확 | +1 | 학생 판정 === 실제(맞다/틀리다) |
| 본인 생각·이유 | 0~2 | 20자 이상이고 해당 개념 키워드(`concept.keywords`) 1개 이상 포함 → 2, 20자 이상만 → 1, 그 외 0 |
| 올바른 개념 제시 | 0~2 | 틀린 주장에만. 수정 설명에 `errorCard.correctKeywords` 2개 이상 → 2, 1개 → 1 |
| 근거 연결 | 0~2 | 근거 선택지에서 `errorCard.evidenceId`와 일치 → 2 |
| 새 사례 적용 | 0~3 | 결과 화면 선택 과제. 데모에서는 교수 화면에서 수동 점수 |

- 과정 감점 −2: 해당 세션에 정답 직행 태그가 있고, 이유 칸 대부분(절반 초과)이 붙여넣기로만 채워졌을 때만. 직행 요청 태그 단독으로는 감점하지 않는다.
- "전부 틀리다" 전략은 맞는 주장 판정에서 점수를 잃으므로 별도 처리 불필요. 단, 결과 화면에 "맞는 주장을 맞다고 인정하는 것도 실력이에요" 안내.

## 확신도 보정 정확도 (`src/lib/calibration.ts`)
- 각 주장: p = 확신도/100 을 "내 판정이 맞을 확률"로 해석, y = 판정이 맞았으면 1 아니면 0.
- Brier = 평균((p − y)²). **보정 정확도 = round((1 − Brier) × 100)** (0~100, 높을수록 좋음).
- 과잉확신 표시: 확신도 ≥ 80인데 틀린 주장 → "확신했지만 틀린 주장" 목록으로 결과 화면에 따로 보여준다(가장 잘 기억되는 지점).

## 정답 직행 감지 (`src/lib/directAnswer.ts`)
- 일반 학습 모드 질문 입력에서 정규식 매칭: `정답만|답만|번호만|해설 ?없이|바로 답|정답 번호|결론만`.
- 매칭 시: 답 대신 경고 + 힌트/검증 모드 안내를 보여주고 세션에 `directAnswerFlag: true` 기록. 이것만으로 감점하지 않는다.
- 외부 AI(Gemini 등) 사용을 감시한다는 표현을 화면에 쓰지 않는다. 서비스 내부 입력만 본다.

## 재인출 퀴즈
- 제출 후 "1주 후 AI 없는 재인출 퀴즈 예약됨(날짜)" 상태를 저장. 발표용으로 "결과 미리 보기"가 미리 준비된 결과 데이터를 연다.
- 재인출 화면에는 AI 입력창을 렌더하지 않는다.

## 교수 대시보드 핵심 지표 (데모는 이 3개를 KpiRow에)
1. 오류 발견률 = 학생들이 '틀리다'로 정확히 판정한 오류 주장 수 / 전체 오류 주장 수
2. 확신도 보정 정확도 = 학생별 값의 평균
3. 1주 후 재인출 점수 = 재인출 퀴즈 평균 정답률
보조: 개념별 혼동률, AI 수용 편향(오류 주장을 '맞다'로 판정한 비율), 정답 직행 시도율, 이유 서술 완성률.
